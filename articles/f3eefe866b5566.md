## はじめに

Prisma 7にアップグレード後、または新規プロジェクトでPrisma 7を使用した際に、`PrismaClient`のインスタンス化時に「requires either "adapter" or "accelerateUrl"」というエラーが発生することがあります。本記事では、実際に遭遇したエラーとその解決方法を詳しく解説します。

## 発生したエラー

`prisma/seed.ts`でPrismaClientをインスタンス化しようとした際に、以下のエラーが発生しました。

```typescript
// prisma/seed.ts
import { PrismaClient } from "@/generated/prisma/client"

const prisma = new PrismaClient({})
```

```bash
PrismaClientConstructorValidationError: Using engine type "client" requires either "adapter" or "accelerateUrl" to be provided to PrismaClient constructor.
Read more at https://pris.ly/d/client-constructor
```

## 環境

- Prisma: 7.2.0
- @prisma/client: 7.2.0
- データベース: SQLite
- Node.js: 24.12.0

## 原因の特定

エラーの原因を調査した結果、以下の問題点が見つかりました。

### `prisma/schema.prisma`の`provider`設定が間違っている

```prisma
// ❌ 間違い
generator client {
  provider = "prisma-client"
  output   = "../src/generated/prisma"
}
```

**これが根本的な原因です。** `prisma-client`プロバイダーは、Prisma AccelerateやPrisma Pulseなど、**Edge環境やServerless環境で使用するための特殊なプロバイダー**です。

通常のNode.jsプロジェクトでは`prisma-client-js`を使用する必要があります。

### Prisma 7でのデータベース接続について

Prisma 7では、使用する環境に応じて2つの接続方法があります：

**方法A: 従来通りの方法（通常のNode.js環境）**
- `schema.prisma`で`url`を指定する従来の方法が使える
- 追加のアダプターは不要
- **ほとんどのケースではこの方法を推奨**

**方法B: アダプターを使用（Edge/Serverless環境）**
- Cloudflare Workers、Vercel Edge Functionsなどの特殊な環境
- データベースアダプターを明示的に指定する必要がある

## 解決方法

環境に応じて2つの解決方法があります。通常のNode.js環境では**方法A**を推奨します。

### 方法A: 従来通りの方法（通常のNode.js環境向け - 推奨）

この方法は最もシンプルで、ほとんどのケースで使用できます。

#### ステップ1: `schema.prisma`を修正

```prisma
generator client {
  provider = "prisma-client-js"  // ✅ prisma-client-jsに変更
  output   = "../src/generated/prisma"
}

datasource db {
  provider = "sqlite"
  url      = env("DATABASE_URL")  // ✅ urlは通常通り指定
}

// ...以下略
```

#### ステップ2: Prismaクライアントを再生成

```bash
npx prisma generate
```

#### ステップ3: PrismaClientをインスタンス化

従来通りの方法でインスタンス化できます。

```typescript
import "dotenv/config"
import { PrismaClient } from "@/generated/prisma/client"

// ✅ シンプルにインスタンス化
const prisma = new PrismaClient()

const main = async () => {
  // データ操作...
}

main()
  .catch((e) => {
    console.error(e)
    process.exit(1)
  })
  .finally(async () => {
    await prisma.$disconnect()
  })
```

#### ステップ4: マイグレーションを実行

```bash
npx prisma migrate dev --name init
```

#### ステップ5: 動作確認

```bash
npx tsx prisma/seed.ts
```

### 方法B: アダプターを使用（Edge/Serverless環境向け）

Cloudflare WorkersやVercel Edge Functionsなど、特殊な環境で使用する場合の方法です。

#### ステップ1: `schema.prisma`を修正

```prisma
generator client {
  provider = "prisma-client-js"
  output   = "../src/generated/prisma"
}

datasource db {
  provider = "sqlite"
  // Edge環境ではurlを削除し、アダプター経由で接続
}
```

#### ステップ2: 必要なパッケージをインストール

```bash
npm install @libsql/client @prisma/adapter-libsql
```

#### ステップ3: Prismaクライアントを再生成

```bash
npx prisma generate
```

#### ステップ4: アダプターを使用してインスタンス化

```typescript
import "dotenv/config"
import { PrismaClient } from "@/generated/prisma/client"
import { PrismaLibSql } from "@prisma/adapter-libsql"

// アダプターを作成
const adapter = new PrismaLibSql({
  url: process.env.DATABASE_URL || "file:./prisma/dev.db"
})

// アダプターを渡してPrismaClientをインスタンス化
const prisma = new PrismaClient({ adapter })

const main = async () => {
  // データ操作...
}

main()
  .catch((e) => {
    console.error(e)
    process.exit(1)
  })
  .finally(async () => {
    await prisma.$disconnect()
  })
```

#### ステップ5: マイグレーションを実行

```bash
npx prisma migrate dev --name init
```

#### ステップ6: 動作確認

```bash
npx tsx prisma/seed.ts
```

## Prisma 7での主な変更点まとめ

Prisma 6から7への主な変更点を整理します。

| 項目 | Prisma 6 | Prisma 7 |
|------|----------|----------|
| generatorのprovider | `prisma-client-js` | `prisma-client-js` (変更なし) |
| データベース接続（通常環境） | `schema.prisma`で`url`指定 | `schema.prisma`で`url`指定（変更なし） |
| データベース接続（Edge環境） | Edge環境のサポートは限定的 | アダプター経由での接続が可能 |
| SQLite使用（通常環境） | 特別な設定不要 | 特別な設定不要（変更なし） |
| SQLite使用（Edge環境） | - | libSQLアダプターを使用 |

## 他のデータベースを使用する場合

### PostgreSQL

```typescript
import { PrismaClient } from "@prisma/client"
import { PrismaPg } from "@prisma/adapter-pg"
import { Pool } from "pg"

const pool = new Pool({
  connectionString: process.env.DATABASE_URL
})

const adapter = new PrismaPg(pool)
const prisma = new PrismaClient({ adapter })
```

必要なパッケージ:
```bash
npm install pg @prisma/adapter-pg
```

### MySQL

**通常のNode.js環境:**
```prisma
datasource db {
  provider = "mysql"
  url      = env("DATABASE_URL")
}
```
```typescript
import { PrismaClient } from "@prisma/client"

const prisma = new PrismaClient()
```

**Edge環境（アダプター使用）:**
```typescript
import { PrismaClient } from "@prisma/client"
import { PrismaMySQL } from "@prisma/adapter-mysql2"
import mysql from "mysql2/promise"

const pool = mysql.createPool({
  uri: process.env.DATABASE_URL
})

const adapter = new PrismaMySQL(pool)
const prisma = new PrismaClient({ adapter })
```

必要なパッケージ:
```bash
npm install mysql2 @prisma/adapter-mysql2
```

**PlanetScale使用時:**
```typescript
import { PrismaClient } from "@prisma/client"
import { PrismaPlanetScale } from "@prisma/adapter-planetscale"

// PlanetScale固有の設定
```

## トラブルシューティング

### エラー: `Unknown property datasourceUrl provided to PrismaClient constructor`

以下のような書き方は**間違い**です：

```typescript
// ❌ 間違い
const prisma = new PrismaClient({
  datasourceUrl: process.env.DATABASE_URL
})
```

正しくは、アダプターを使用します：

```typescript
// ✅ 正しい
const adapter = new PrismaLibSql({
  url: process.env.DATABASE_URL
})
const prisma = new PrismaClient({ adapter })
```

### エラー: `SQLITE_ERROR: no such table`

マイグレーションが実行されていない可能性があります。

```bash
npx prisma migrate dev
```

### エラー: `PrismaLibSQL is not a constructor`

クラス名のスペルミスの可能性があります。正しくは`PrismaLibSql`（最後が小文字の`l`）です。

```typescript
// ❌ 間違い
import { PrismaLibSQL } from "@prisma/adapter-libsql"

// ✅ 正しい
import { PrismaLibSql } from "@prisma/adapter-libsql"
```

## まとめ

Prisma 7で「requires either "adapter" or "accelerateUrl"」エラーが発生した場合、主な原因は**`schema.prisma`の`provider`設定が`prisma-client`になっている**ことです。

### 重要なポイント

1. **通常のNode.js環境では従来通りの方法が使える**
   - `provider = "prisma-client-js"`を使用
   - `schema.prisma`で`url`を指定する従来の方法が引き続き有効
   - アダプターは不要

2. **Edge/Serverless環境ではアダプターを使用**
   - Cloudflare Workers、Vercel Edge Functionsなど
   - データベースアダプターを明示的に指定する必要がある

3. **Prisma 7は後方互換性を維持**
   - 既存のPrisma 6のコードは基本的にそのまま動作する
   - `provider = "prisma-client"`を使用していた場合のみ変更が必要

ほとんどの場合、`provider`を`prisma-client-js`に変更するだけで解決します。特別な理由がない限り、通常のNode.js環境では従来通りの方法（方法A）を推奨します。
